1. QUÉ HACE EL PROGRAMA
-------------------------------------------------------------------------------
El programa revisa un archivo de código PHP y busca errores de escritura
(errores léxicos). Trabaja así:

  1. Busca los archivos que terminan en ".php" en la misma carpeta donde
     está el programa.
  2. Lee cada archivo sin cambiarle nada.
  3. Revisa tres cosas:
        - los nombres de las variables (identificadores),
        - las etiquetas de inicio y fin de PHP:  <?php  y  ?>
        - los comentarios:  //  y  #
  4. Crea un archivo nuevo con el mismo nombre, terminado en "-errores.log".
     Ese archivo es una copia del .php con cada línea numerada. Debajo de
     cada línea que tiene un problema aparece el error encontrado.

El programa funciona solo en consola (CMD). No tiene
ventanas ni botones o una interfaz grafica.


2. QUÉ SE NECESITA
-------------------------------------------------------------------------------
  - Una computadora con Windows.
  - Java instalado, desde la versión 8 o más nueva. La mayoría de las computadoras ya
    lo tienen.
    Para comprobarlo: abrir el CMD, escribir
        java -version
    y presionar Enter. Debe aparecer un número de versión.
  - Solo para ver o compilar el código: Apache NetBeans 24 o superior.


3. CÓMO EJECUTARLO (PASO A PASO)
-------------------------------------------------------------------------------
El programa ya viene compilado en la carpeta "dist", junto con el archivo PHP
de ejemplo. Tras descargar el .zip y descomprimirlo en una carpeta de nombre
cualquiera se deben seguir estos pasos para su correcta ejecución:

  Paso 1. Abrir la carpeta del proyecto y entrar a la carpeta "dist".
          Ahí hay dos archivos:
              ProyectoCompiladores1.jar   (el programa)
              CodigoProyecto.php          (el código PHP que se va a revisar, se adjunta el .php base de AprendeU)

  Paso 2. Abrir el Símbolo del sistema (CMD) en esa carpeta.
          Forma fácil: en el Explorador de archivos, hacer clic en la barra
          de direcciones (donde aparece la ruta de la carpeta), escribir CMD
          y presionar Enter. Se abrirá el CMD con la ruta del "dist".

  Paso 3. Escribir este comando y presionar Enter:
              java -jar ProyectoCompiladores1.jar

  Paso 4. En la ventana aparece un resumen parecido a este:
              === Analizador lexico PHP ===
              Carpeta: C:\...\ProyectoCompiladores1\dist

              Archivo: CodigoProyecto.php
                Lineas: 53 | Tokens: 148 | Errores: 0
                Log generado: CodigoProyecto-errores.log

  Paso 5. En la carpeta "dist" aparece un archivo nuevo:
              CodigoProyecto-errores.log
          Abrirlo con el Bloc de notas para ver el resultado.

  Para revisar otro archivo PHP:
     Copiarlo a la carpeta "dist" y repetir el paso 3. Puede tener cualquier
     nombre, siempre que termine en ".php". Si hay varios archivos .php, el
     programa los revisa todos y crea un archivo .log para cada uno.

  Opcional, para ver más detalle:
              java -jar ProyectoCompiladores1.jar -tokens
     Muestra además la lista de tokens (cada palabra o símbolo encontrado y
     su tipo) y la lista de variables encontradas.


4. CÓMO LEER EL RESULTADO
-------------------------------------------------------------------------------
El archivo "-errores.log" es una copia exacta del .php, con dos agregados:

  - Cada línea empieza con su número, de 4 dígitos, y un espacio.
  - Si una línea tiene un error, el error aparece en el renglón de abajito, con
    este formato:   Error NÚMERO. Descripción

Ejemplo de una línea con dos errores:

    0005 $nombre_estudiante = "Carlos";
    0006 $1cantidad = 4; $if = 5;
    Error 201. El identificador '$1cantidad' no puede iniciar con un dígito después de '$'
    Error 204. El identificador '$if' usa la palabra reservada 'if' y no puede ser asignado
    0007

Los errores que no pertenecen a una línea (por ejemplo, que falte la etiqueta
de cierre ?>) aparecen al final del archivo.


5. CÓMO PROBAR QUE DETECTA ERRORES
-------------------------------------------------------------------------------
  Forma 1: modificar el archivo de ejemplo.
     1. Abrir  dist\CodigoProyecto.php  con el Bloc de notas.
     2. Cambiar algo. Por ejemplo, en la línea 6, cambiar
            $cantidad_notas = 4;      por      $1cantidad = 4;
     3. Guardar el archivo.
     4. Ejecutar de nuevo:   java -jar ProyectoCompiladores1.jar
     5. Abrir el .log: debajo de la línea 6 aparece el Error 201.

  Forma 2: usar las pruebas incluidas.
     La carpeta "pruebas" tiene 24 copias del archivo de ejemplo. Cada una
     tiene un error puesto a propósito (3 de ellas no tienen errores, para
     comprobar que el programa no marca errores falsos).
     1. Copiar todos los archivos de la carpeta "pruebas" a la carpeta "dist".
     2. Ejecutar:   java -jar ProyectoCompiladores1.jar
     3. Se crea un archivo .log por cada archivo .php.
     4. El archivo  pruebas\esperado.txt  indica qué se cambió en cada prueba
        y qué error debe aparecer.


6. CÓMO COMPILARLO EN NETBEANS
-------------------------------------------------------------------------------

  1. Abrir NetBeans.
  2. Menú File > Open Project y elegir la carpeta del proyecto.
  3. Hacer clic derecho sobre el proyecto y elegir "Clean and Build"
     (o presionar Shift + F11). Al terminar debe decir BUILD SUCCESSFUL.
  4. IMPORTANTE: "Clean and Build" borra todo lo que hay en la carpeta
     "dist" y crea de nuevo el archivo .jar. Por eso, después de compilar,
     hay que copiar otra vez el archivo PHP:
         copiar  recursos\CodigoProyecto.php  a la carpeta  dist
  5. Ejecutar como se explica en la sección 3.


7. LISTA DE ERRORES QUE DETECTA
-------------------------------------------------------------------------------
  Sobre el archivo (se muestran en la ventana de comandos)
    101  No hay ningún archivo .php en la carpeta
    102  El archivo no termina exactamente en .php (no se revisa)
    103  No se pudo leer el archivo

  Sobre los identificadores (nombres de variables)
    201  Hay un número justo después de $           Ejemplo: $1variable
    202  Hay un símbolo justo después de $          Ejemplo: $-dato
    203  Hay un carácter no permitido en el nombre  Ejemplo: $suma@notas
    204  Se usa una palabra reservada como nombre   Ejemplo: $if = 10;
    205  Hay un $ sin nombre                        Ejemplo: $ = 5;
    206  Falta el $ al inicio del nombre            Ejemplo: nombre = "Ana";

  Sobre las etiquetas <?php y ?>
    301  Hay algo antes de <?php (texto, espacios o líneas en blanco)
    302  La etiqueta de inicio está mal escrita     Ejemplo: <? php
    303  No existe la etiqueta de inicio <?php
    304  La etiqueta de cierre está mal escrita     Ejemplo: ? >
    305  No existe la etiqueta de cierre ?>
    306  Hay código después de ?> en la misma línea
    307  La etiqueta ?> no está en la última línea
    308  Hay espacios o líneas en blanco después de ?>

  Sobre los comentarios
    401  Comentario con una sola barra              Ejemplo: / texto
    402  Texto suelto que no es código (por ejemplo, un comentario que
         continúa en la línea siguiente sin // ni #)

  Generales
    501  Carácter que no pertenece al lenguaje      Ejemplo: @
    502  Texto entre comillas sin cerrar            Ejemplo: echo "hola;


8. CÓMO ESTÁ ORGANIZADO EL CÓDIGO
-------------------------------------------------------------------------------
El código está en la carpeta  src\proyectocompiladores1  y se divide en cuatro
grupos (paquetes). Cada archivo cumple una sola tarea.

  Main.java                          Dirige todo: llama a cada parte en orden.

  io (leer y escribir archivos)
    LocalizadorArchivo.java          Busca los archivos .php junto al programa.
    LectorArchivoPHP.java            Lee el archivo sin cambiarle nada.
    ArchivoFuente.java               Guarda las líneas leídas.
    EscritorLog.java                 Crea el archivo -errores.log.

  lexico (las 4 etapas del análisis léxico)
    AnalizadorLexico.java            ETAPA 1. Obtención de tokens: recorre cada
                                     línea letra por letra y la separa en
                                     pedazos (lexemas).
    ClasificadorTokens.java          ETAPA 2. Clasificación: dice de qué tipo
                                     es cada pedazo (variable, número, texto,
                                     palabra reservada, comentario...).
    Patrones.java                    ETAPA 3. Patrón: tiene las reglas de cada
                                     tipo y la lista de palabras reservadas.
    ValidadorLexema.java             ETAPA 4. Validación: revisa que cada
                                     pedazo cumpla sus reglas.
    Token.java, TipoToken.java       Representan un token y sus tipos.

  validacion (las reglas que revisa la etapa 4)
    ValidadorIdentificadores.java    Reglas de los nombres de variables.
    ValidadorEtiquetas.java          Reglas de <?php y ?>.
    ValidadorComentarios.java        Reglas de los comentarios.

  errores
    CodigoError.java                 La lista de errores con su número.
    ErrorLexico.java                 Un error encontrado.
    GestorErrores.java               Guarda los errores de cada línea.

Orden en que trabaja el programa con cada archivo .php:
    leer  ->  etapa 1  ->  etapa 2  ->  etapa 4 (usa las reglas de la etapa 3)
          ->  escribir el archivo .log


9. DECISIONES TOMADAS
-------------------------------------------------------------------------------
  - Archivos que se revisan: todos los que terminan en ".php" y están junto
    al programa. Así no depende de un nombre ni de una ruta fija.
  - Dónde se muestran los errores: debajo de la línea donde ocurren, 
    porque es más fácil de corregir (o al menos a gusto personal así lo es).
  - Numeración: 4 dígitos y un espacio. Ejemplo: "0001 <?php"
  - Mayúsculas y minúsculas en las variables: $total y $Total son dos
    variables distintas.
  - Palabras reservadas: no se distinguen mayúsculas, porque en PHP "IF" y
    "if" son la misma palabra. Por eso $if, $If y $IF son error. (o eso fue lo 
    que entendi sobre como manejar las mayusculas para el proyecto)
  - La regla de palabras reservadas se aplica a la variable que está a la
    izquierda del signo "=". Los signos "==", ">=", "<=" y "!=" son
    comparaciones, no asignaciones.
  - Lectura del archivo: se lee completo y no línea por línea, para saber si
    hay algo antes de <?php o después de ?> (por ejemplo, un Enter al final).
  - Versión de Java: el programa se compila para Java 8, para que funcione
    en cualquier computadora, tenga un Java viejo o nuevo. Se probó con
    Java 8 y con Java 26.
  - Tildes: en la ventana de comandos se escriben sin tilde; en el archivo
    .log sí se conservan.


10. LIMITACIONES
-------------------------------------------------------------------------------
  - Solo se revisan comentarios de una línea (// y #), como pide el enunciado.
    Los comentarios de varias líneas /* */ no se reconocen.
  - Un texto entre comillas debe empezar y terminar en la misma línea.
  - Una línea que empieza con una sola barra "/" se toma como un comentario
    mal escrito.
  - El contenido de los textos entre comillas no se revisa.
  - Una resta escrita sin espacios entre una variable y una palabra ($a-total)
    se toma como un nombre de variable con guion (Error 203).
  - El programa no revisa la gramática. Por ejemplo, si falta un punto y coma
    no lo reporta, porque eso no es un error léxico.
